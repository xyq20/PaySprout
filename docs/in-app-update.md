# 双端应用内更新

启动后检查 GitHub 官方 Releases 的最新稳定版本；也可从菜单栏 / 系统托盘、紧凑菜单和设置中手动检查。发现新版时提示版本与发布说明，用户选择下载，下载完成后选择重启更新。检查失败不影响收入与计时，不反复弹错；后台检查每 6 小时最多一次。

更新只接受 xyq20/PaySprout 仓库固定命名的 ZIP、严格的三段稳定版本和 GitHub 提供的 SHA-256 摘要。下载使用 GitHub Release asset API；校验大小、摘要和包结构后再准备安装。拒绝同版、旧版、预发布、草稿、错误平台、缺失摘要与越界归档路径。无 token、镜像、运行时代码注入或系统权限提升。

Mac 校验应用标识、版本和代码签名，在当前应用目录准备新包。独立 shell 助手等待旧进程退出，保留旧包、替换、启动新包并等待启动确认；失败恢复旧包。Windows 从自带运行时的主程序复制出独立更新助手，同样等待退出、替换 EXE、启动确认及失败回滚。设置位于用户目录，不参与替换。应用位于只读 DMG / 无写入权限的目录时明确提示移动应用。

验证覆盖：版本与发布元数据边界、伪造摘要、归档路径、HTTP 失败、下载取消、真实临时目录的替换成功和回滚、Windows 发布包的启动确认。测试只使用隔离目录。现有 0.1.0 必须手动安装一次新版以获得更新器；原生二进制更新需重启。
